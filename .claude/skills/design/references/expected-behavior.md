# Generic expected-behaviour policy

Use only when project instructions and matching behaviour-policy skills provide no policy.

Read the request and relevant discussion. Separate observed behaviour, requested outcomes, proposed causes and suggested fixes. Establish intended behaviour from the user's requirements and confirmed decisions; do not treat a reporter's suggestion as an accepted requirement.

Existing code and tests show current behaviour. Read relevant documentation and prior decisions for intended behaviour, and ask the user to resolve conflicting or ambiguous expectations. Follow the calling skill's rules for asking questions, if it has any, and wait for answers.

State the resulting expected outcomes and their supporting requirements or decisions in the calling skill's output. Do not copy the discussion into it.
